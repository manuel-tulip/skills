# Milestone entry

Use for a routine successful checkpoint without substantive debugging. A detailed diary request overrides this mode. If meaningful failures or design decisions arise, escalate to the investigation format rather than losing their context.

```markdown
## Step N: Milestone title

Short prose describing the outcome and why it matters.

### Prompt Context
**User prompt (verbatim):** (see Step N; quote the authored request on first use)
**Assistant interpretation:** Requested milestone.
**Inferred user intent:** Intended outcome.

### Evidence and commits
- Command/result/revision or receipt references.

### Noteworthy decisions or failures
- Exact relevant detail, or none observed.

### Remaining requirements and next action
- Stable task/requirement IDs, actual uncertainty and next concrete action; N/A if none.
```

Do not generate another independent current-state ledger when tasks and a receipt already own that information. Links are sufficient; historical prose remains immutable unless explicitly corrected with attribution.
