# Phase checklists

## Start
- Confirm the actual requested scope and repository state; preserve unrelated edits and historical artifacts.
- Locate/create the ticket and its tasks/diary. Read the contract and relevant guide before implementation.
- Resolve instruction ownership once: diary format, docmgr mechanics, specialist delivery policy.

## Implement or investigate
- Read evidence before conclusions. Keep version/source references for claims.
- Test changed behavior and its dependencies. A negative test's expected failure is not automatically workflow friction.
- Record exact meaningful failures promptly; explicit detailed-diary requests use investigation entries.

## Checkpoint
- Commit a coherent validated change and record evidence/commit links once.
- Use real milestone commands when available; otherwise existing task/changelog commands remain sufficient.
- Keep primary file relations focused, with full changed paths recoverable from the commit/receipt.

## Resume
- Read the current request and latest relevant checkpoint, compare current revisions, then choose the next unresolved requirement.
- Load absent/changed instructions and necessary references. Do not assume a digest means instructions are remembered.
- Respect higher-priority mandatory reads and user pins; phase conventions do not change the harness.

## Validate and close
- Validate all changed diagrams/assets and dependent documents. Shared renderer/policy changes invalidate all dependents.
- Audit every explicit requirement, including integration and actual media/visual checks when required.
- Run ticket hygiene, resolve relevant warnings and leave uncertainty open.
- Deliver only requested outputs, using the specialist upload policy. Record the actual success evidence level.
